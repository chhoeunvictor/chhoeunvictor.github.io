Overview

Vertex Flow style guide

This guide defines the content standards for Vertex Flow — a fictional Google Cloud data pipeline tool for ML engineers and data teams. It covers voice, terminology, formatting, and UI writing patterns for all product surfaces: console UI, API reference, Help Center, and release notes.

Follow this guide when writing any customer-facing content for Vertex Flow. When this guide conflicts with the Google developer documentation style guide, defer to the Google guide. Use this guide for Vertex Flow-specific conventions.

Note

This is a portfolio writing sample by Victor Chhoeun. Vertex Flow is a fictional Google Cloud product. This guide demonstrates content strategy, voice governance, and Google-style documentation practice.

Overview

Writing principles

Apply these principles to every piece of content you write for Vertex Flow.

  • Write for the task, not the feature. Users care about what they can do, not how the product is built. Lead with outcomes and actions.
  • Use present tense. Write "the pipeline runs" not "the pipeline will run." Present tense is more direct and easier to scan.
  • Use active voice. Write "Vertex Flow processes the data" not "the data is processed." Active voice identifies who does what.
  • Be concise. Remove every word that doesn't earn its place. If a sentence works without a word, cut it.
  • Be specific. Use exact names, values, and paths. "Click Save pipeline" is clearer than "save your work."
  • Write for scanning. Use headings, numbered steps, and short paragraphs. Most users scan until they find what they need.
Voice & Tone

Voice attributes

Vertex Flow's voice is consistent across all surfaces. It reflects Google Cloud's broader voice: knowledgeable, clear, and human — never cold, condescending, or overly casual.

✓ Vertex Flow is
✓
Clear and direct
Lead with the most useful information. Get to the point.
✓
Technically confident
Users are engineers. Don't oversimplify — be accurate and precise.
✓
Human and approachable
Use contractions. Write the way a smart colleague talks, not the way a spec reads.
✓
Action-oriented
Every touchpoint moves the user toward a goal. No dead ends.
✕ Vertex Flow isn't
✕
Jargon-heavy or opaque
Don't use internal product or engineering jargon that users won't recognize.
✕
Overly formal or stiff
Avoid "Please be advised," "utilize," or "in order to."
✕
Overcelebrating
Don't add "Amazing!" to routine actions. Engineers find it patronizing.
✕
Vague or noncommittal
Avoid "might," "could potentially," or "in some cases" unless genuinely uncertain.
Voice & Tone

Tone by context

The voice stays constant. The tone adapts to context. An engineer debugging a failed pipeline needs a different tone than one exploring a new feature for the first time.

Console UI and product copy

Tone: Direct, efficient, minimal. Users are in the middle of a task.

Example · console confirmation

Pipeline deployed. It's now running in us-central1.

Error messages

Tone: Calm, factual, and action-oriented. Give users what they need to recover — don't alarm them.

Example · pipeline error

The pipeline failed at the data-ingestion step. Check your source credentials and retry. If the issue persists, see Troubleshoot pipeline errors.

Reference documentation

Tone: Neutral, precise, and scannable. Eliminate editorial opinion entirely. Users are looking up facts.

Example · API parameter description

pipeline_id (string, required): The unique identifier for the pipeline. The value must be 3–63 characters, start with a letter, and contain only lowercase letters, numbers, and hyphens.

Onboarding and quickstart guides

Tone: Warm, encouraging, and step-by-step. Users may be new to Google Cloud or Vertex Flow.

Example · quickstart introduction

This quickstart shows you how to create and run your first Vertex Flow pipeline. You'll connect a data source, configure a transformation step, and deploy the pipeline to Google Cloud. The process takes about 15 minutes.

Voice & Tone

Person and pronouns

Use second person ("you")Required

Address the user directly using "you." Don't use "the user," "they," or "one."

✓ Correct
You can monitor pipeline runs in the Runs tab.
✕ Incorrect
Users can monitor pipeline runs in the Runs tab.
Use "we" sparingly — only when the system acts on the user's behalfPreferred
✓ Acceptable
We'll send you an email when the pipeline finishes.
✕ Avoid
We recommend that you enable logging for all pipelines.

Terminology

Terms to avoid

The following terms are prohibited or discouraged in Vertex Flow content. Flag these in editorial reviews.

Prohibited phrases
✕
"Simply" or "just"
Implies the task is easy — condescending if it isn't.
✕
"Please" in instructions
Remove it. "Click Save" is more direct than "Please click Save."
✕
"Utilize"
Always replaceable with "use."
✕
"In order to"
Always replaceable with "to."
Avoid these patterns
✕
Passive voice in instructions
"The pipeline can be configured" → "Configure the pipeline."
✕
Future tense in UI copy
"The pipeline will start" → "The pipeline starts."
✕
Vague time references
"Recently," "soon," "shortly" — use exact values or relative timestamps.
✕
Anthropomorphizing the product
"Vertex Flow thinks…" or "Vertex Flow wants…" — avoid intent language.
Formatting

Capitalization

Use sentence case for all headings and UI labelsRequired

Use sentence case everywhere: headings, button labels, navigation items, and tab names. Capitalize only the first word and proper nouns.

✓ Correct
Create a pipeline · Pipeline settings · View run history
✕ Incorrect
Create A Pipeline · Pipeline Settings · View Run History
Capitalize Google Cloud product namesRequired

Capitalize official Google Cloud product and service names. Don't capitalize generic terms.

  • ✓ Vertex AI, BigQuery, Cloud Storage, Vertex Flow
  • ✓ "Store artifacts in Cloud Storage"
  • ✕ "Store artifacts in cloud storage"
Bold UI elements when referenced in instructionsRequired

When you refer to a UI element the user needs to interact with, bold it — buttons, tabs, menu items, and field labels.

✓ Correct
Click Deploy, then select your target region.
✕ Incorrect
Click Deploy, then select your target region.
Formatting

Punctuation

Use the Oxford commaRequired

Always use the Oxford comma in lists of three or more items.

✓ Correct
Configure the source, transform, and output steps.
✕ Incorrect
Configure the source, transform and output steps.
Don't use terminal punctuation in UI labelsRequired

Don't end button labels, tab names, or navigation items with periods. Do use periods in tooltips, helper text, and full-sentence descriptions.

  • ✓ Button: Deploy pipeline
  • ✓ Helper text: "Enter a name for your pipeline. Names must be unique within a project."
  • ✕ Button: Deploy pipeline.
Formatting

Numbers and dates

Spell out numbers zero through nineRequired

In running text, spell out zero through nine. Use numerals for 10 and above. Always use numerals in UI labels and technical contexts.

✓ Running text
A pipeline can have up to five steps in the free tier and 50 in the paid tier.
✓ UI copy
3 runs failed · Timeout: 5 min · Max retries: 3

Formatting

Procedures and steps

Write step-by-step instructions as numbered lists. Each step contains one action. Start each step with an imperative verb.

One action per stepRequired

Don't combine multiple actions in a single step. If the user needs to do two things, write two steps.

✓ Correct
1. Click Add step.
2. Select Data transform from the menu.
✕ Incorrect
1. Click Add step and select Data transform from the menu.

Example procedure

Example · Create and deploy a pipeline
1
In the Google Cloud console, go to Vertex Flow.
2
Click Create pipeline.
3
In the Name field, enter a name for your pipeline. Names must be 3–63 characters and contain only lowercase letters, numbers, and hyphens.

Add steps to your pipeline, then click Deploy.
Formatting

Notes and warnings

Use callouts sparingly. Overusing them dilutes their impact. Follow the Google Cloud callout hierarchy.

TypeWhen to useExample
NoteSupplementary information that's useful but not criticalPipeline names can't be changed after creation.
CautionInformation that may cause data loss or unexpected behavior if ignoredDeleting a pipeline also deletes all associated artifacts.
WarningActions that may cause irreversible harm or security riskDon't share service account keys in public repositories.
Note

Pipeline names can't be changed after creation. If you need a different name, delete the pipeline and create a new one.

Caution

Deleting a pipeline also deletes all associated artifacts and run history. This action can't be undone.

Warning

Don't include service account keys in your pipeline configuration. Use Secret Manager to store and access credentials securely.
